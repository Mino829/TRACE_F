# 展示画面の音（提出先）

展示画面（`/display`）で鳴らす音の置き場所です（issue #27）。
音を作ったら、**このフォルダに、下の名前でファイルを入れてください**。名前が合っていれば、コードを変えなくても展示画面がその音を使います。
まだファイルがない音は、ブラウザの中で作った仮の音が鳴ります。

## 入れるファイル（優先度 A）

| ファイル名 | 音 | 鳴るとき | 長さ・形 |
|---|---|---|---|
| `scan.mp3` | 到着QR を読めた音 | 来場者が QR を読み、再生に切りかわる瞬間 | 0.5〜1 秒 |
| `play-bgm.mp3` | 再生中の BGM | 軌跡の再生のあいだ（1 人 1 分前後） | **ループする曲**。人によって長さが違うので、何秒でもくり返せて、どこで終わっても不自然にならない作り |
| `arrive.mp3` | ShibaLab に着いた音（締め） | 「ShibaLab に到着しました」が出る瞬間 | 3〜5 秒。再生中の BGM はここで 1 秒かけて消える |
| `wait-bgm.mp3` | 待っているときの BGM | トップ画面（到着QR を表示中） | **ループする曲**。静かに、数分。主張しすぎない |

- テーマは ShibaLab の RAY（白黒・光・網点）。電子音・グリッチ・やわらかいシンセあたり
- BGM どうしの切りかえは、展示画面のほうで 1.5 秒のフェードでつなぎます

## ファイルの形式
- **MP3**（128〜192kbps）がおすすめ。OGG でもよい（`play-bgm.ogg` のように、同じ名前で拡張子だけ変える）
- 1 ファイル 2MB くらいまで（画面を開くたびに読み込むので、小さいほうがよい）
- 音の大きさ：いちばん大きい所が 0dB を超えない（-1dB くらいまで）。4 つの音の大きさをだいたいそろえる。細かい音量はあとで `sounds.json` で合わせる
- WAV など元の大きいファイルは、ここには入れずに手元に残しておいてください

## ループのつなぎ目（BGM だけ）
- ファイルの頭から終わりまでをそのままくり返します。つなぎ目でプツッと鳴らないように、頭と終わりがつながる形で書き出してください
- イントロのあとの部分だけをくり返したいときは、`sounds.json` の `loopStart` と `loopEnd`（秒）で決められます：

```json
"play": { "files": ["play-bgm.mp3"], "loop": true, "volume": 0.6, "loopStart": 4.0, "loopEnd": 36.0 }
```

- `volume`（0〜1）は、その音だけの大きさです

## 出し方
- GitHub の Mino829/TRACE_F で、このフォルダ（`public/display/sound/`）にファイルを入れて PR を作る
  - ブラウザなら：音のブランチ（`feature/27-sound`）を開く → このフォルダ → 「Add file」→「Upload files」
- Git がむずかしければ、ファイルを @code-yuto に送ってもらえれば入れます

## 鳴らして確かめる
- `npm run dev` で http://localhost:3000/display を開き、「♪ 音を出す」を押す（ブラウザは一度クリックするまで音を出しません）
- 「▶ テスト再生」で、QR を読めた音 → 再生中の BGM → 着いた音、の流れを聞けます
- URL に `?sound=1` を付けると、右下に「どの音が本物のファイルで、どれがまだ仮の音か」が出ます
- `?volume=0.6` で全体の大きさ、`?mute=1` で消音
